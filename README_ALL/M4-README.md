# M4. Нельзя архивировать товар и отключать склад, пока на них есть остатки и открытые документы

## Что было
Каталог разрешал архивировать товар с остатком и открытыми заявками, склад можно было отключить при открытых документах.
Остатки и документы оставались со ссылкой на «исчезнувшую» сущность.

## Что сделано
- **inventory-service** `UsageController`: `GET /api/v1/stock/products/{id}/usage` (остаток, открытые поступления,
  активные резервы) и `GET /api/v1/stock/warehouses/{id}/usage` (остаток, открытые поступления, черновики списаний,
  выдач и корректировок). Роли: кладовщик и администратор.
- **request-service** `RequestUsageService` + `GET /api/v1/requests/usage?productId=|warehouseId=`: число открытых заявок
  (от SUBMITTED до READY_FOR_ISSUE; черновики не считаются: при отправке номенклатура и склад проверяются заново).
  Роли: кладовщик и администратор. В `RequestController` добавлен один метод.
- **catalog-service** `ProductUsageGuard`: `POST /products/{id}/archive` отвечает 409 `PRODUCT_IN_USE` с перечнем причин
  (остаток, поступления, резервы, заявки). Повторная архивация уже архивного товара остаётся идемпотентной.
- **warehouse-service** `WarehouseUsageGuard`: `PATCH /warehouses/{id}` с `active=false` отвечает 409 `WAREHOUSE_IN_USE`
  с перечнем причин. Проверка идёт в контроллере до транзакции (запросы к соседям не держат её).
- Секции по-прежнему: блокировка с товаром разрешена, архивация запрещена (B2).

## Настройки
Catalog и warehouse ходят в соседние сервисы с JWT администратора: `app.services.inventory-url` (по умолчанию
`http://localhost:8084`) и `app.services.request-url` (`http://localhost:8085`). Если ключи в ваших `application.yaml`
называются иначе, задайте их или поправьте значения по умолчанию. Миграций нет.

## Проверить
- Товар с остатком: архивация даёт 409 `PRODUCT_IN_USE`; после списания остатка и закрытия заявок архивируется.
- Склад с открытой заявкой или поступлением в статусе RECEIVING: отключение даёт 409 `WAREHOUSE_IN_USE`.
- Если inventory или request недоступны, архивация и отключение не выполняются (ошибка соседнего сервиса).
- Фронтенд: показывать `details` ответа (список причин) в диалоге архивации и отключения.

## Не сделано (остаток M4)
- Отключённый работник не теряет назначенные строки комплектации автоматически: кладовщик заменяет его вручную
  (интерфейс показывает флаг `active` из справочника пользователей).
- Токен отключённого пользователя действует до 8 часов: отзыв токенов это пункт P1-8 плана безопасности
  (короткий access-токен и refresh с отзывом).
- Гонка: между проверкой и архивацией может появиться новый остаток или заявка; повторная проверка после архивации
  невозможна без распределённой блокировки (окно мало, последствия исправляются восстановлением товара).
