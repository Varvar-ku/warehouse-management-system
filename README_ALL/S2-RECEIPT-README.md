# S2 для inventory-service: ReceiptService без внешних вызовов в транзакции

Один файл: `inventory-service/.../service/ReceiptService.java` (накопительный: содержит S1 и B4-зависимости, поэтому
S1-архив должен быть применён раньше).

## Что изменено
- `create`: склад (warehouse-service) и номенклатура (catalog-service) запрашиваются **до** открытия транзакции.
- `update`: номенклатура запрашивается до транзакции (если переданы позиции).
- `recommend` и `confirm`: три фазы.
  1. короткая транзакция: снимок черновика (статус DRAFT, позиции в обычных объектах);
  2. без транзакции: номенклатура из catalog, занятость (короткая читающая транзакция), расчёт в warehouse-service;
  3. короткая транзакция: блокировка документа (`FOR UPDATE`), проверка, что документ остался прежним (статус DRAFT и
     тот же состав позиций), запись рекомендации и (для `confirm`) решений, смена статуса.
  Если за время расчёта документ изменили (позиции заменены, подтверждён, отменён), операция отклоняется:
  409 `CONCURRENT_MODIFICATION` или `INVALID_STATUS`; побочных эффектов во внешних сервисах нет (расчёт только читает),
  поэтому аренда, как в request-service, здесь не нужна.
- `confirm` теперь защищён блокировкой документа, а не только версией.

## Проверить
- Фронтенд: код `CONCURRENT_MODIFICATION` показывать как «Документ изменился, обновите и повторите» (уже описано в
  плане фронтенда для ошибок).
- Сценарии приёмки: создание, `recommend`, `confirm` с решениями кладовщика, размещение.
- Вызов `occupancyService.forWarehouse` теперь идёт в `TransactionTemplate`: если метод сам `@Transactional`, ничего
  не меняется.
