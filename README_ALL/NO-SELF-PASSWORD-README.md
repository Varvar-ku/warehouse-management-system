# Пароли задаёт только администратор

Логин пользователь и так сменить не может: `UpdateUserRequest` не содержит логина, создаёт учётные записи только ADMIN.
Закрыта смена пароля самим пользователем.

## Что изменено (auth-service)
- `AuthController.changePassword`: при `app.security.self-service-password-change: false` (по умолчанию) отвечает
  403 `PASSWORD_CHANGE_DISABLED`. Вернуть смену пароля можно, поставив `true`, без правки кода.
- `application.yaml`: `app.security.self-service-password-change: false`. Файл взят из версии S4 (с блоком Kafka).
- `UserService`: подсказка при создании первого администратора теперь указывает `POST /users/{id}/reset-password`.

## Как администратор меняет пароли
`POST /api/v1/users/{id}/reset-password {"newPassword": "..."}`, в том числе для собственной учётной записи.
Событие `user.password_reset` попадает в журнал аудита (S4).

## Сделать на фронтенде
Убрать форму смены пароля из профиля (`ProfilePage`) и показывать подсказку «Пароль меняет администратор».
Показывать понятный текст на код `PASSWORD_CHANGE_DISABLED`, если форма всё же осталась.

## Что стоит знать
- Если администратор потеряет свой пароль и других администраторов нет, восстановить доступ можно только правкой БД.
  Держите минимум двух администраторов.
- Администратор знает пароль, который выдал: действия под этой учётной записью труднее оспорить. Лучше выдавать
  случайный пароль, а пароль в журнал и в логи не писать (сейчас не пишется).
- Токены не отзываются при сбросе пароля (до 8 часов, пункт P1-8 плана безопасности): после сброса старая сессия
  пользователя ещё жива. Пока P1-8 не сделан, это остаётся ограничением.
