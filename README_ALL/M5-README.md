# M5. Ошибки ввода данных больше не превращаются в «Нераспределено»

## Что было
- Числовому атрибуту можно было задать единицу любого типа (длине в килограммах): движок размещения не мог её перевести
  (`UnknownUnitException`) и молча отправлял позицию в «Нераспределено».
- Конвертер поддерживает CM, а в каталоге такой единицы не было.
- Материалы и типы деталей в ограничениях секции были свободным текстом, не связанным со справочником каталога;
  опечатка делала секцию «никогда не принимающей» нужные позиции. То же для единицы вместимости.

## catalog-service
- Новый `UnitDimension` (LENGTH, MASS, COUNT, OTHER). У единицы поле `dimension` (по умолчанию OTHER), у определения
  атрибута необязательное `dimension` (LENGTH или MASS, только для NUMBER).
- `ProductService`: единица значения атрибута должна подходить по типу величины (иначе 400 с понятным текстом).
  Для атрибутов с типом величины единица **обязательна** (`app.catalog.require-attribute-unit`, по умолчанию true).
- Миграция `V6__unit_dimensions.sql`: колонки, типы для MM, M, KG, PCS и атрибутов LENGTH, WIDTH, HEIGHT, DIAMETER, MASS,
  новая единица CM. Если V6 занят, возьмите следующий свободный номер.
- DTO (`UnitRequest/Response`, `AttributeDefinitionRequest/Response`) получили поле `dimension` в конце.
  Ответ `ProductResponse` не менялся (его читают другие сервисы со строгим разбором).
- Все файлы взяты из версий с аудитом S4 (`ProductService`, `ReferenceService`).

## warehouse-service
- `SectionConstraintsValidator` + `CatalogReferences`: при создании и изменении секции единица вместимости, типы деталей
  и материалы сверяются со справочниками каталога (`/units`, `/product-types`, значения атрибута MATERIAL); ошибка 400
  показывает допустимые значения. Проверка идёт в `SectionController` до транзакции (запросы к каталогу не держат её).
  Отключается `app.placement.validate-against-catalog: false`. Если каталог недоступен, сохранить секцию нельзя.
- URL каталога: `app.services.catalog-url` (по умолчанию `http://localhost:8082`); если в warehouse он задан иначе,
  поправьте. JWT администратора пересылается в каталог.

## ВАЖНО проверить
- Все единицы каталога с типом LENGTH должны быть и в `app.placement.length-units` warehouse-service (сейчас MM, M, CM;
  CM поддерживается конвертером). Автоматической сверки нет: добавляя единицу длины в каталог, добавьте её и в настройки склада.
- Существующие данные. В catalog_db найти значения с неподходящей или отсутствующей единицей:

      SELECT p.sku, pa.attribute_code, u.code AS unit
      FROM product_attributes pa
      JOIN products p ON p.id = pa.product_id
      JOIN attribute_definitions d ON d.code = pa.attribute_code
      LEFT JOIN units u ON u.id = pa.value_unit_id
      WHERE d.dimension IS NOT NULL AND (u.id IS NULL OR u.dimension <> d.dimension);

  Старые записи не ломаются, но при следующем изменении товара потребуют единицу.
- Фронтенд: форма атрибутов должна отправлять `valueUnitId` для длины и массы и фильтровать список единиц по `dimension`;
  в формах единиц и определений добавить поле «тип величины».

## Не сделано
- Сверка ограничений существующих секций с каталогом (проверяются только новые сохранения).
- Проверка единицы вместимости секции на совместимость с единицами позиций (требует решения заказчика о массе и вместимости, D9).
