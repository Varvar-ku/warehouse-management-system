# Изменения фронтенда

Архив накопительный: он заменяет предыдущие `frontend-changes.zip` и `frontend-changes-2.zip` и содержит все новые и изменённые файлы
относительно исходного `src.zip` (включая правки под новый бэкенд из первой части). Пути относительно корня
проекта фронтенда. Распакуйте поверх проекта. Зависимости в `package.json` не менялись (только скрипт `test`).

## Часть 1. Правки под новый бэкенд

### Заявки (машина статусов)
- `UNDER_REVIEW` больше не существует: проверка наличия сразу даёт `APPROVED` или `PARTIALLY_AVAILABLE`.
  Статус остался только как подпись для старой истории и убран из фильтров.
- Кладовщик может отклонить заявку из `SUBMITTED`, `APPROVED` и `PARTIALLY_AVAILABLE` (раньше кнопка была привязана к `UNDER_REVIEW` и не появлялась).
- Пользователь может отменить свою заявку только до резерва (`SUBMITTED`, `APPROVED`, `PARTIALLY_AVAILABLE`); после резерва отменяет кладовщик.
- Повторная проверка наличия доступна из `APPROVED` и `PARTIALLY_AVAILABLE`.
- Идемпотентность (`Idempotency-Key`) в request-service: создание и отправка заявки, проверка, резерв, готовность, выдача, закрытие, отклонение и отмена.
  Ключ привязан к содержимому запроса и живёт до успешного ответа: двойной клик не создаёт два черновика.

### Приёмка и размещение
- Новое решение `REJECT_LINE` и статус позиции `REJECTED`: позицию (брак, потеря) можно закрыть с нулевым приходом, в том числе ещё не размещённую (`PENDING`), поэтому приёмка не зависает.
- Выбор секции при размещении показывает только активные секции без «Нераспределено» (как требует бэкенд).
- В форме приёмки нельзя выбрать прошедший срок годности: просроченный товар бэкенд не принимает.

### Остатки, недостачи, корректировки (новое)
- В остатках появился признак `onHold` («На проверке»): такая строка не резервируется и не попадает в «только доступные».
- Раздел **«Недостачи»**: список, действие «Найдено», оформление корректировки по выбранным недостачам одного склада.
- Раздел **«Корректировки»**: список и карточка; одобрение администратором (не автором), проведение и отмена кладовщиком (с Idempotency-Key).

### Уведомления
- Добавлены типы `REQUEST_REJECTED` и `REQUEST_CANCELLED`.

## Часть 2. Продолжение по плану (этапы 6, 7, 8)

### Этап 6. Администратор
- **Пользователи** (`/admin/users`): список, создание, правка (ФИО, контакты, роли, активность), сброс пароля.
  При выборе опасного сочетания ролей (Пользователь+Кладовщик, Кладовщик+Администратор) показывается предупреждение о разделении обязанностей.
- **Каталог** (`/admin/catalog`): товары (поиск, архив и восстановление, форма атрибутов строится по определениям), типы товаров, единицы, атрибуты.
- **Склады и секции** (`/admin/warehouses`): склады; секции с ограничениями (размеры, вместимость, типы, материалы), статусы ACTIVE/BLOCKED/ARCHIVED.
  Для зоны «Нераспределено» ограничения и статус не отправляются (бэкенд их защищает).
- **Правила размещения** (`/admin/rules`): список, редактор условий (типы, материалы, размеры «равно» или «диапазон»), история версий.
- **Аудит** (`/audit`): фильтры по действию (в том числе префикс `request.*`), объекту, исполнителю, периоду; детали события.

### Этап 7. Отчёты (`/reports`)
Девять отчётов на одной странице-конфигурации (`features/reports/config.ts`): остатки на дату, движение детали, поступления, выдачи, списания,
заявки, расхождения, журнал комплектации, сводка по работникам. Серверная пагинация до 500 строк, выгрузка в CSV (разделитель `;`, BOM,
защита от формул, до 5000 строк).

### Этап 8 (частично)
- Все страницы грузятся лениво (`React.lazy`), `src/App.tsx` переписан на таблицу маршрутов с теми же ролями.
- Тесты логики (22 проверки): кнопки по статусам заявки, CSV, условия правил, сборка атрибутов. Файлы `*.test.ts`, конфиг `vitest.config.ts`.
- `Dockerfile` и `nginx.conf`: SPA с запасным маршрутом, прокси `/api/` на gateway (`GATEWAY_URL`), CSP и заголовки безопасности.
- README и `frontend-development-plan.md` обновлены (таблица статусов этапов).

## Что нужно сделать вам
1. `npm i -D vitest`, затем `npm test` (тесты я прогнал только собственной заглушкой, настоящий Vitest в среде недоступен).
2. `npm run build`: полноценная проверка типов не выполнялась (нет `node_modules` и сети), проверены синтаксис и неиспользуемые импорты.
3. Добавить в gateway маршруты `/api/v1/shortages/**` и `/api/v1/adjustments/**` (см. выше).
4. Перед выкладкой за nginx доработать `ClientIp` в auth-service: сейчас все пользователи за nginx попадут в один счётчик защиты входа.

## Часть 3. Правки по замечаниям
1. **Количество только в штуках.** Единица выбирается нигде: во всех таблицах, формах и отчётах стоит «шт» (константа `PCS` в `shared/format.ts`), поля количества целые.
   Колонки «Ед.» убраны, в заголовках добавлено «, шт». В карточке товара единица не выбирается: берётся «Штука» (PCS). Вместимость секции задаётся только числом, в штуках.
2. **«Принять» для размещения.** Работник сначала принимает задание на размещение, затем подтверждает позиции. В бэкенде у задания размещения нет состояния «принято»
   (только OPEN, COMPLETED, CANCELLED), поэтому принятие хранится в браузере работника (`features/tasks/placementAccept.ts`); задание с уже подтверждённой позицией считается принятым везде.
   Чтобы принятие было общим и попадало в аудит, нужен эндпоинт на бэкенде; тогда меняется только этот хук.
3. **Секцию у работника выбрать нельзя.** Работник видит секцию, назначенную кладовщиком, и подтверждает количество. Секцию по-прежнему выбирает кладовщик при подтверждении приёмки и при возврате позиции на размещение.
4. **«Остатки» убраны у работника** (меню и маршрут).
5. **Типы при создании.** Тип секции выбирается из списка (Стеллаж, Полка, Ячейка, Пол, Паллетное место; в БД это свободная строка, значения можно менять в `SECTION_TYPES`). Тип товара выбирался из списка и ранее.
6. **Склад не выбирается пользователем.** В заявке склад подставляется автоматически (единственный активный); в списке заявок фильтр и колонка склада показаны только кладовщику и администратору.
7. **Список заявок:** по 15 строк на странице, выбор размера страницы убран.
8. **Колокольчик** показывает три последних уведомления (клик открывает заявку), кнопки «Все уведомления» и «Прочитать все». Страница «Уведомления» содержит весь список, последние три в нём тоже есть.
9. **Без подтверждения** у кладовщика «Проверка наличия» и «Выдать»: действие выполняется по клику. Комментарий при выдаче больше не вводится. Остальные окна подтверждения (резерв, готово к выдаче, закрыть, отклонить, отменить) сохранены.
